# Bend 2.0.26 against the scorecard's 2.0.3

How did upstream Bend change on these workloads between the scorecard's revision, 2.0.3 ([b9d1352](https://github.com/bendlang/bend/commit/b9d1352c9f45632447f40a2e927355c92f2be58c)), and 2.0.26 ([6a77e12](https://github.com/bendlang/bend/commit/6a77e1246c351055cb15031267a7c76c87036cbc))?

On the CPU, 2.0.26 takes about 3% longer (geometric mean over 20 rows at one and at 16 threads). HotSpot takes 34–38% longer, N-Queens 12–13% and summation 9%, while ray tracing takes 6–7% less. On the GPU, 2.0.26 takes about 3% less time over 19 rows: shared-graph BFS takes 40% less, symbolic regression 26% less and HotSpot 20% less, while ray tracing takes 38% longer. UTS still stops at the GPU stack limit.

The archived scorecard binaries and freshly built 2.0.26 binaries ran alternately under the same machine load, five rounds per cell, with every execution checked against its expected output. The [scorecard](benchmarks/summary/index.html) keeps its 2.0.3 measurements.

## Results

Each value is 2.0.26 time divided by 2.0.3 time for the complete program, the median of five paired rounds. Below 1.00 means 2.0.26 is faster.

The large changes repeat in every round. The five paired ratios are 1.31–1.36 for HotSpot on one thread, 0.598–0.602 for BFS on the GPU, 1.37–1.46 for ray tracing on the GPU and 0.72–0.75 for symbolic regression on the GPU.

The ray-tracing GPU slowdown comes from the compiler's line-count inlining threshold for natives. Upstream commit [6e16f4e4](https://github.com/bendlang/bend/commit/6e16f4e4f45811415b49f47c79cbdcdad4d1e45f) shortened the bounce-loop native below that threshold, so it is now inlined into a shader that is itself inlined four times. The GPU program grew from 4,248 to 6,696 SASS instructions.

## Method

Each cell compares the archived 2.0.3 binary from the scorecard's own run with a 2.0.26 binary built from the same benchmark source; the published workload sources are byte-identical between the two revisions, and the other ports are fixed in this harness. Every execution uses the command and correctness check from its own run's plan, so each version must reproduce the expected output. Each cell gets one warmup per version, then five rounds in which both versions run once in seeded random order. The ratio for a round divides the 2.0.26 time by the 2.0.3 time from that round. GPU executions run under the harness's GPU activity monitor, which admits only the approved transcription worker.

Paired runs were needed because other work shared the host during these measurements: a long decompilation job, compiler builds and GPU inference. Absolute times from the same day drifted from the scorecard by up to 45%. Merkle on the GPU measured 206 ms against the scorecard's 142 ms, while its paired ratio is 1.03. These absolute times are therefore not placed next to the scorecard's comparison columns, which were measured on a quiet machine.

Pricing and game search time repeated requests through instrumented adapters and are not part of the paired set. Their unpaired 2.0.26 runs passed every correctness check but were recorded under the same load.

## Evidence

The paired results are in [runs/scorecard-paired-cpu-20260923-212816/summary.json](runs/scorecard-paired-cpu-20260923-212816/summary.json) (21 cells) and [runs/scorecard-paired-cpu-20260923-222329/summary.json](runs/scorecard-paired-cpu-20260923-222329/summary.json) (the remaining 38), produced by [scorecard_paired_cpu.py](scorecard_paired_cpu.py). The first run stopped when an unapproved GPU process appeared; its completed cells were kept and the second run measured the rest. Samples, including warmups, are in each run's `samples.jsonl`.

The 2.0.26 binaries come from Bend-only harness runs pinned to 6a77e12: `runs/29d5e01964534ceb39fa` (published workloads), `runs/c0935eb35be8886bd61c` (UTS), `runs/d64d29e70a9489c31ff3` (HotSpot), `runs/1cd8bdb5fb5a2aeea8f7` (BFS) and `runs/scorecard-summation-20260923-200411`, configured by the `scorecard-*.toml` files. Runs stopped by external GPU activity or by a build failure are retained: `runs/2a3dece2e3aeb40ea701`, `runs/c5b04b94711d53dd74cc`, `runs/scorecard-summation-20260923-142049`, `runs/5c68a08e2071e809d573` and `runs/mnk-sustained-20260923-212538`.
