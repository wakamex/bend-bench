Timing boundaries

Complete-program rows include startup, input preparation, computation, transfers and output. Each cell is a median of ten correctness-gated executions after warmup. Option pricing and game-search rows exclude startup and use medians of three process means, with 30 measured requests or batches after two warmups. Quote and game-search timings end when their results are available on the CPU.

Relative time divides each cell by the fastest measured time in its row. Lower is better. Compare implementations within a row, not ratios across different workloads. Highlighting is descriptive, not a significance test.

Comparison implementations

Published workloads use serial C and project-written OpenMP, with project CUDA, CUB sorting, cuBLAS matrix multiplication and cuDF edit distance. UTS uses canonical BOTS OpenMP tasks and a project CUDA frontier traversal. Summation uses fused serial C++, OpenMP and CUB reduction. HotSpot uses corrected Rodinia OpenMP and CUDA pyramid height 1. BFS uses GAP and Gunrock. Pricing and game search use project-written OpenMP/CUDA.

Sorting algorithms and data representations differ. Published-workload and UTS GPU additions come from separate runs with matching inputs and output contracts. The game-search row uses one matched CPU/GPU run. Bend GPU reaches its runtime stack limit on UTS; the failed run has no timing. Invalid and superseded measurements, kernel-only timings and the separate reduction crossover sweep are excluded.
