# Pricing, m,n,k search and BFS

This extension tests whether one Bend source can run usefully on CPU and CUDA across independent numerical paths, exact game-tree search and graph traversal. Rodinia HotSpot supplies the stencil workload in the preceding queue. No results are claimed until correctness, timing and profiling gates pass.

## Contracts

- Pricing: arithmetic Asian call, spot and strike 100, one-year maturity, risk-free rate 0.05, volatility 0.2; 64/256 equally spaced observations, 4,096/32,768/262,144 paths. Timed work includes path simulation and reduction to the mean option price. Both that price and every discounted payoff are compared with an independently evaluated FP64 implementation. Paths use FP32; OpenMP accumulates in FP64, while Bend and CUDA CUB use FP32 reductions. Absolute/relative tolerances are 0.002 and 0.0001. This tests execution of the stated discretely monitored model, not a claim of production-quality random streams or variance reduction. The identical Park-Miller/Box-Muller streams make backend errors distinguishable from Monte Carlo sampling noise.
- m,n,k: 16 distinct reproducibly generated legal nonterminal positions per game, 4×4 connect-3 and 5×5 connect-4, with six/eight empty squares. A tuple-board memoized Python solver independently computes exact outcomes. Full terminal search has no heuristic cutoff. Bend evaluates terminal-pruned branches in parallel; the conventional CPU and CUDA controls use alpha-beta pruning. Compare time to the same exact answers, not nodes/second. CUDA splits root moves; OpenMP distributes positions. These are locally authored controls, not established best-in-class game engines. This is exact endgame solving, not MCTS and not a reproduction of published empty-board 7×7/8×8 solutions.
- BFS: one directed graph with 1,024/16,384/262,144 vertices and up to eight incoming neighbors per vertex. Edges are deterministic hash-derived, deduplicated, and identical across implementations. Compare every distance from source zero, including unreachable vertices, with an independent queue BFS. GAP supplies direction-optimizing OpenMP BFS, Gunrock v2.0.0 supplies CUDA BFS. Bend uses immutable balanced trees and level-synchronous pull traversal; it generates neighbors implicitly, while the baseline wrappers load explicit edge lists. Thus graph construction/storage and startup are part of the end-to-end comparison and differ by representation. These finite random graphs are not the complete GAP input portfolio.

## Baseline status

GAP commit `2972aeb2703165bafd921222f4ed7196f542d3a8`, Gunrock v2.0.0 commit `a2e9f04aa7a14aa4d2922ffc6a5fcbba9d451df6`, and ModernGPU commit `267cc8d02c03f00f1656f1205c61c946a1e530b0` are pinned locally. Gunrock v2.0.0 was selected for its CUDA-native API, avoiding the current main branch's additional HIP platform dependencies. Wrappers preserve the upstream BFS algorithms. CUB/Thrust use the already documented Clang compatibility patch.

The application suite uses CUDA 12.4: Gunrock v2.0.0 references device-property fields removed in CUDA 13.1. Its `SM_TARGET=86` setting follows the upstream build contract. Clang requires an explicit `__device__` annotation on Gunrock's managed benchmark counter; that one declaration change and a final newline are preserved in the source diff. Metrics collection is disabled, matching the upstream default. CCCL's optional NVTX annotations are disabled because this Clang/toolkit combination rejects their host-only destructor inside device Thrust calls; Nsight CUDA kernel tracing remains enabled. Source-check diagnostics are retained in `runs/application-source-checks.jsonl`.

Pricing uses local OpenMP/CUDA arithmetic controls. It must not be described as a tuned finance-library comparison. NVIDIA's [Asian-option sample](https://github.com/NVIDIA/cuda-samples/tree/master/cpp/2_Concepts_and_Techniques/MC_SingleAsianOptionP) is a follow-up external baseline requiring an explicit random-stream and output contract. Exact-search comparisons are likewise local controls. No global optimality claim is made.

The NVIDIA sample is archived locally in `sources/cuda-samples` at commit `5443602d89ed99aede2e4b7bf329daddeadb320e` for that follow-up; it is not part of the queued measurements. The three BFS inputs have 8,161, 131,046 and 2,097,127 distinct directed edges, respectively. All vertices are reachable from source zero, with maximum distances 5, 6 and 8. The game corpora contain win/loss outcomes in both 4×4 cases and win/draw/loss outcomes in both 5×5 cases; the complete move histories and reference answers are generated and preserved with each prepared run.

## Local m,n,k project review

Inspected `/code/mnk` at clean commit `17f085da3a201eba597f42470b357e8929e45c3d` without modifying it. Its `src/unified_mcts.rs` implements neural-guided MCTS; `src/fixed_suite_eval.rs` contains depth-limited alpha-beta with heuristic leaf evaluation. That is useful context for a future full-MCTS extension but is not an exact oracle for this endgame contract. No trained model or historical win rate is imported into these results.

## Timing

Each cell receives a separate correctness run, excluded warmup and ten measurements. CPU thread counts are 1, 2, 4, 8, 16 and 32; this host has 16 physical cores and SMT. Nsight profiles are separate from wall-time measurements. Full output validation is mandatory for each timing/profile sample. GPU activity monitoring and the shared execution lock prevent overlap with the preceding queue. No benchmark or source file used by the preceding queue is modified while it is active.
# BFS offload correction, September 18

The original port called `solve!(64n, init(depth, 0), False{})`. Evaluating the parallel `init` argument before the offload seam entered CPU scheduling; all three Bend BFS traces contained CUDA setup but no kernel launches. The corrected port calls `bfs!()` with initialization and solving inside that function. Correctness checks pass at 1,024, 16,384 and 262,144 vertices, and Nsight verifies 28, 32 and 40 launches respectively. Verification evidence is in `runs/8ce685c54502b6cd1286/offload-verification.jsonl`. The native smoke test now requires a real kernel trace for Bend BFS. Use `applications-bfs.toml` for the replacement measurements; original v6 pricing and game-search evidence remains valid in its separate report.
